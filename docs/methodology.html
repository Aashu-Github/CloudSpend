← Back to home03 — Methodology

Evidence before action.

Every input source becomes the same canonical model before versioned deterministic rules produce advisory findings.

01
PROVIDER BOUNDARY

Normalize first.

Demo fixtures, uploads, and live Boto3 calls terminate at adapters. Optimization rules never parse AWS responses or spreadsheets directly.

FixtureProviderFileProviderAwsProvider
02
VALIDATION GATE

Reject malformed data.

Pydantic validates canonical objects. Missing memory remains unknown rather than becoming zero, while cost provenance remains actual, allocated, estimated, or unavailable.

PydanticSource lineageCost provenance
03
RULE ENGINE

Use multiple signals.

Idle detection combines CPU average, p95/max, network evidence, burst protection, and observation-window quality. Rightsizing, scheduling, orphan storage, and anomaly rules have separate criteria.

CPUNetworkBurst scoreConfidence
04
HUMAN REVIEW

No destructive MVP.

Findings use “candidate,” “review,” and “estimated savings.” CloudSpend does not stop instances, resize infrastructure, or delete volumes.
